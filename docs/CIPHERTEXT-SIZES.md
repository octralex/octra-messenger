# Ciphertext and bootstrap sizes

Scope: actual `3aab2d992035076dd216ad8808710d3a5a56063a` measurements from
`tests/size_sweep.ml`, generated by `tests/run_size_sweep.sh` on Hetzner. No real keys or conversations.
The selected recipient route is `recipient-x25519-aes-gcm`; the other routes are same-key-holder representation
baselines only. No PVAC route is presented as recipient encryption.

## Method

- Plaintext lengths: 0, 1, 7, 8, 16, 32, 64, 128, 256, 512, 1024, 2048, 4096 and 16384 bytes.
- Additional fixtures: short ASCII, multilingual UTF-8, repeated `A`, deterministic random bytes and embedded
  zero bytes. The UTF-8 generator repeats whole codepoints and uses ASCII only for the final fill; it never slices
  a multibyte character. Length is always bytes, not character count. No compression.
- Five seal/open repetitions per measured case: one cold followed by four warm. Warm median/max excludes the cold
  sample; overall max includes all five. Verification has four warm repetitions. Allocation is the delta for each
  case. `/usr/bin/time -v` records peak RSS. Benchmark IDs come from fixture kind/length labels, never plaintext;
  the testkit feeds those deterministic vectors through the same production seal implementation.
- OCaml 4.14.2, dune 3.23.0, Linux 7.0.0-43-generic, x86-64. Separate endpoint and sweep executable hashes,
  source/tree identities, commands, compiler, opam lock, Mirage 2.1.0 source/library hashes and venue are in
  `receipts/recipient/environment.json` and `receipts/recipient/sizes-environment.json`. The complete sweep used
  49.38 s user CPU (49.56 s elapsed) and had maximum RSS 91,172 KiB (89.04 MiB).
- `native_bytes` is the encrypted payload. `envelope_bytes` includes the 161-byte fixed header, context and
  encrypted payload. Current context is 77 bytes, so overhead is 266 bytes. `wire_bytes` is base64 of the complete
  envelope plus JSON string quotes. Selected signed sizes and OU are measured in `receipts/chain/fees-and-sizes.json`;
  explicit fee burn and production admission remain unmeasured.
- PVAC slots use a four-byte plaintext length followed by data, padded with zeroes to seven-byte field slots.
  Vector uses one ciphertext per slot vector; scalar-chunk uses one ciphertext per slot. Scalar-chunk above 128
  plaintext bytes was not measured because of its time cost; that is a measurement limit, not an API limit.

Raw evidence: `receipts/recipient/sizes.csv` and `receipts/recipient/sizes-time.txt`.

fixed-bucket rule.

## Limits and headroom

At the inspected node pin, transaction gossip JSON is capped at 5,000,000 bytes, HTTP adds 65,536 bytes of
headroom, program message fields allow 10,000,000 bytes, a contract storage value allows 4,194,304 bytes, and
the program execution lane has a 4 MiB budget. The maximum signed RPC admission and the segment's frame rejection
are measured below; these source constants still do not prove whole-envelope storage or production acceptance.

- The selected 16 KiB message's 22,202-byte base64 envelope is far below these limits.
- The profile caps plaintext at 2,999,299 bytes, ciphertext at 2,999,327 bytes and envelope bytes at 3,000,000.
  The absolute envelope cap permits 4,000,002 base64-plus-quote bytes with the maximum 512-byte context; the
  separate 194,302-byte transaction-overhead budget brings that total to 4,194,304 bytes. In the endpoint's
  77-byte context, exact-cap plaintext produced a 2,999,565-byte envelope and 3,999,422 wire bytes and
  round-tripped; cap-plus-one was rejected. The current chain segment still requires exactly 2,048 bytes per
  frame, so a whole large envelope is not one accepted storage value.
- The same-key PVAC vector at 16 KiB is 1,878,512 raw bytes and 2,504,686 base64 bytes, below the named storage
  and gossip bounds but expensive to produce and scan. Its envelope/final transaction is unmeasured.
- The 3,128,595-byte PVAC public key is below raw storage limits, and its 4,171,462-byte base64 string is below
  the 5,000,000-byte gossip bound and 4 MiB by 22,842 bytes. Actual registration JSON/signature/policy overhead
  can change that headroom, so acceptance is not inferred from the key alone.
- No 2/4/64 KiB bucket is frozen. Bucket selection must follow the selected recipient profile, actual native
  serialization and measured chain transaction encoding.

Timing and memory data include independent cold/warm cases and maxima. They do not establish sustainable rates,
finalized throughput at scale, explicit fee burn or a production cryptographic profile.
